## Автоматизация IPvGO

IPvGO — стратегическая мини-игра на захват территории, доступная в DefComm в New Tokyo или в CIA в Sector-12. Формируйте сети роутеров на сетке, чтобы контролировать открытое пространство и получать множители характеристик и favor, но следите, чтобы противоборствующая фракция не окружила и не уничтожила вашу сеть!

За базовыми инструкциями зайдите в DefComm или CIA, чтобы открыть текущую подсеть, и посмотрите раздел «How to Play». Этот документ посвящён именно написанию скриптов для автоматизации захвата подсетей — он будет полезнее, когда вы уже поиграли в несколько подсетей.

Полный список методов IPvGO с их описаниями и документацией — на [странице документации API IPvGO](../../../../../markdown/bitburner.go.md).

&nbsp;

#### Обзор

В своей основе правила Go очень просты. Благодаря этому по ним можно написать очень простой скрипт для автоматического сбора Node Power с подсетей IPvGO.

Этот скрипт можно постепенно улучшать, добавляя ему всё больше инструментов и типов ходов для поиска, делая его всё более уверенным в захвате территории на текущей подсети.

Этот документ начинается с большого числа деталей и примеров кода, чтобы помочь вам стартовать, но по мере продвижения переходит к более высокоуровневому проектированию алгоритмов и псевдокоду. Если застряли при реализации каких-то из этих идей, обсудите это на [официальном сервере Discord](https://discord.gg/TFc3hKD).

### План скрипта: начинаем с основ

&nbsp;

#### Проверка допустимости хода

API `ns.go` даёт немало полезных инструментов для понимания текущего состояния подсети.

`ns.go.analysis.getValidMoves()` возвращает двумерный массив true/false, показывающий, можно ли поставить роутер на данную клетку.

Проверить, допустим ли ход `x,y`, можно так:

```js
const validMoves = ns.go.analysis.getValidMoves();

if (validMoves[x][y] === true) {
  // Do something
}
```

&nbsp;

#### Выбор случайного хода

Простейший тип хода — и запасной вариант, если не нашлось ничего другого, — выбрать случайный допустимый ход.

Сетку `validMoves` можно получить через `getValidMoves()`, как сказано выше. `board` берётся из `ns.go.getBoardState()`, об этом подробнее позже.

Заполнять абсолютно все узлы на поле, однако, было бы плохой идеей. Если сеть теряет контакт со всеми пустыми узлами, она будет уничтожена! Поэтому оставляйте немного «воздуха», исключая некоторые ходы из случайно выбираемых.

Один из способов — исключить узлы, у которых и X, и Y-координата чётные:

```js
/**
 * Choose one of the empty points on the board at random to play
 */
const getRandomMove = (board, validMoves) => {
  const moveOptions = [];
  const size = board[0].length;

  // Look through all the points on the board
  for (let x = 0; x < size; x++) {
    for (let y = 0; y < size; y++) {
      // Make sure the point is a valid move
      const isValidMove = validMoves[x][y] === true;
      // Leave some spaces to make it harder to capture our pieces.
      // We don't want to run out of empty node connections!
      const isNotReservedSpace = x % 2 === 1 || y % 2 === 1;

      if (isValidMove && isNotReservedSpace) {
        moveOptions.push([x, y]);
      }
    }
  }

  // Choose one of the found moves at random
  const randomIndex = Math.floor(Math.random() * moveOptions.length);
  return moveOptions[randomIndex] ?? [];
};
```

Эту идею также можно улучшить, сосредоточившись сначала на конкретной области или углу, а не сразу растекаясь по всему полю.

&nbsp;

#### Совершение ходов

Теперь, когда простой тип хода готов, его можно использовать для игры в текущей подсети!

Функция `await ns.go.makeMove(x, y)` делает выбранный ход `x,y`. Учтите, что она возвращает `Promise`, то есть нужен `await`.

Функция `await ns.go.passTurn()` используется, если подходящих ходов не найдено. Если ИИ тоже спасует (или уже спасовал ранее), игра на этом закончится.

И `makeMove()`, и `passTurn()` при использовании с await возвращают объект, сообщающий, каков ответ ИИ и не закончилась ли игра.

```js
{
  // If the opponent moved or passed, or if the game is now over.
  type: "move" | "pass" | "gameOver";
  x: number | null; // Opponent move's x coord (if applicable)
  y: number | null; // Opponent move's y coord (if applicable)
}
```

&nbsp;

Вместе с `getRandomMove()`, реализованной выше, у нас готов каркас скрипта. Пример реализующей это функции `main()` — ниже. Найдите новую подсеть через интерфейс, затем запустите свой скрипт и посмотрите, как он играет!

```js
/** @param {NS} ns */
export async function main(ns) {
  let result, x, y;

  do {
    const board = ns.go.getBoardState();
    const validMoves = ns.go.analysis.getValidMoves();

    const [randX, randY] = getRandomMove(board, validMoves);
    // TODO: more move options

    // Choose a move from our options (currently just "random move")
    x = randX;
    y = randY;

    if (x === undefined) {
      // Pass turn if no moves are found
      result = await ns.go.passTurn();
    } else {
      // Play the selected move
      result = await ns.go.makeMove(x, y);
    }

    // Log opponent's next move, once it happens
    await ns.go.opponentNextTurn();

    await ns.sleep(200);

    // Keep looping as long as the opponent is playing moves
  } while (result?.type !== "gameOver");

  // TODO: add a loop to keep playing
  // TODO: reset board, e.g. `ns.go.resetBoardState("Netburners", 7)`
}
```

### Добавляем ходы на расширение сети

Впрочем, просто играть случайными ходами не слишком эффективно. Следующий шаг — использовать состояние поля, чтобы пытаться захватывать территорию.

`ns.go.getBoardState()` возвращает простую сетку, отражающую текущий вид поля. Роутеры игрока помечены `X`, роутеры противника — `O`.

Пример состояния поля 5x5 с несколькими сетями каждого игрока:

```angularjs
[  "XX.O.",
   "X..OO",
   ".XO..",
   "XXO..",
   ".XOO.", ]
```

По состоянию поля можно посмотреть все узлы, соседствующие с заданной точкой, обращаясь к соседним парам координат.

Например, узел «к северу» от текущей точки `x, y` можно получить через `board[x + 1]?.[y]`. Если там свой роутер, значение будет `"X"`. (Значение будет undefined, если `x,y` лежит на северном краю подсети.)

Эту информацию можно использовать, чтобы решать, куда ставить роутеры.

Чтобы расширить область, контролируемую сетями игрока, сильным ходом будет подключение к своим роутерам (когда это возможно). Реализуется это очень похоже на `getRandomMove()`, с дополнительной проверкой наличия соседнего своего роутера. Для каждой точки на поле:

```text
Detect expansion moves:
   For each point on the board:
      * If the empty point is a valid move, and
      * If the point is not an open space reserved to protect the network [see getRandomMove()], and
      * If a point to the north, south, east, or west is a friendly router

      Then, the move will expand an existing network
```

Когда возможно, такой ход-расширение стоит предпочесть случайному ходу. Если не нашлось ни того, ни другого — пасуйте.

Эту идею можно улучшить: зарезервированные места можно пропускать, если узлы принадлежат разным сетям. См. `ns.go.analysis.getChains()`.

После реализации этого скрипт будет стабильно набирать очки на подсети против большинства противников (по крайней мере на больших полях), а иногда даже сможет удачно выиграть у самых слабых фракций.

&nbsp;

#### Дальнейшие шаги

Улучшить скрипт можно ещё во многом. Во-первых, сейчас он играет только одну игру, и его приходится перезапускать каждый раз! Кроме того, он пока не сбрасывает подсеть по завершении игры.

Кроме того, скрипт знает лишь про несколько типов ходов и пока не умеет захватывать или защищать сети.

&nbsp;

#### Завершение дублирующихся скриптов

Поскольку активна всегда только одна подсеть, вам не нужно, чтобы работали несколько копий вашего скрипта, конкурирующих друг с другом. Может быть полезно при запуске завершать все другие скрипты с тем же именем, что и ваш скрипт IPvGO. Это можно сделать через `ns.getRunningScript()`, чтобы получить сведения о скрипте, и `ns.kill()`, чтобы удалить старые копии скрипта.

&nbsp;

### Тип хода: захват сетей противника

Если у сети противника остался последний открытый порт, размещение роутера в этом пустом узле захватит и уничтожит всю эту сеть.

Чтобы узнать, какие сети под угрозой захвата, используйте `ns.go.analysis.getLiberties()` — она показывает, сколько пустых узлов/открытых портов у каждой сети. Как и с `getBoardState()` и `getValidMoves()`, число свобод (открытых портов) для сети в заданной точке можно получить по её координатам `[x][y]` в сетке, которую возвращает `getLiberties()`.

```text
Detect moves to capture the opponent's routers:
   For each point on the board:
      * If the empty point is a valid move, and
      * If a point to the north, south, east, or west is a router with exactly 1 liberty [via its coordinates in getLiberties()], and
      * That point is controlled by the opponent [it is a "O" via getBoardState()]

      Then, playing that move will capture the opponent's network.
```

&nbsp;

### Тип хода: защита своих сетей от захвата

`getLiberties()` также можно использовать, чтобы обнаружить собственные сети под угрозой захвата и поискать ходы для их спасения.

```text
Detect moves to defend a threatened network:
   For each point on the board:
      * If the empty point is a valid move, and
      * If a point to the north, south, east, or west is a router with exactly 1 liberty [via its coordinates in getLiberties()], and
      * That point is controlled by the player [it is a "X" via getBoardState()]

      Then, that network is in danger of being captured.


   To detect if that network can be saved:

   * Ensure the new move will not immediately allow the opponent to capture:
      * That empty point ALSO has two or more empty points adjacent to it [a "." via getBoardState()], OR
      * That empty point has a friendly network adjacent to it, and that network has 3 or more liberties [via getLiberties()]

      Then, playing that move will prevent your network from being captured (at least for a turn or two)
```

&nbsp;

### Тип хода: удушение сетей противника

Иногда сеть противника ЕЩЁ нельзя захватить, но, окружив её роутерами со всех сторон, её можно будет захватить следующим ходом. (Или хотя бы заставить противника тратить ходы на её защиту.)

Подходов тут много, но самый простой — искать любую вражескую сеть с наименьшим оставшимся числом свобод (в идеале 2) и находить безопасную точку для роутера, соприкасающуюся с ней.

Чтобы такой ход тут же не был отбит захватом, убедитесь, что у выбранной точки есть два соседних пустых узла либо она соприкасается со своей сетью с тремя и более свободами. (Это та же проверка, что и в ходе на защиту своей цепи.)

&nbsp;

### Тип хода: расширение связей своих сетей с пустыми узлами

Чем больше пустых узлов соприкасается с сетью, тем она сильнее и тем большую территорию она контролирует. Поэтому размещение роутеров, соприкасающихся со своей сетью и одновременно с как можно бо́льшим числом открытых узлов, часто оказывается сильным ходом.

Логика похожа на защиту своих сетей от немедленного захвата. Ищите свою сеть с наименьшим числом открытых портов и находите соседний с ней пустой узел, соприкасающийся сразу с несколькими другими пустыми узлами.

&nbsp;

### Тип хода: окружение пространства для контроля пустых узлов

Ключевая часть стратегии Go — полностью окружать группы пустых узлов. В примерах в начале этого документа отдельные узлы просто оставляются пустыми в надежде, что так и останется, но делать это можно гораздо лучше.

В качестве простого подхода ищите возможные ходы, которые:

- соприкасаются с двумя отдельными пустыми узлами (открытыми областями, которые он разделит);
- соприкасаются со своей фишкой и краем поля (или со второй своей фишкой из другой цепи, отличной от первой).

Так находятся ходы, соединяющие ваши цепи между собой или с краем поля и попутно разделяющие пустое пространство. Это позволяет контролировать пространство, попутно усложняя захват ваших цепей.

&nbsp;

### Выбор хорошего хода

Полезно иметь несколько вероятных ходов на выбор, но для сильного скрипта Go важно ещё и правильно выбирать между ними. В некоторых случаях, если такой тип хода доступен, играть его почти всегда стоит (например, защита сети от немедленного захвата или захват уязвимой вражеской сети).

У каждой фракции IPvGO есть несколько ходов, которые она почти всегда выбирает (например, The Black Hand всегда захватывает, если может). Хорошим стартом для соперничества с такими скриптами будет простой список приоритетов. Экспериментируйте, чтобы найти, что работает лучше всего!

Эту идею, впрочем, можно улучшить, учитывая такую информацию, как размер сети, находящейся под угрозой или уязвимой для захвата. Например, вероятно, стоит пожертвовать одним роутером ради захвата крупной вражеской сети. Добавление двух новых открытых портов крупной сети полезно, но ограничение сети противника до одного открытого порта может оказаться ещё лучше.

&nbsp;

### Другие типы ходов

**Подготовка вторжения на территорию противника**

Пустые области, полностью окружённые и контролируемые одним игроком, видны через `ns.go.analysis.getControlledEmptyNodes()`. Но то, что область сейчас контролируется противником, ещё не значит, что её нельзя атаковать! Начните с окружения вражеской сети снаружи, и тогда её можно будет захватить, атакуя пространство, которое она окружает и контролирует. (Учтите, что это работает только для сетей с единственным внутренним пустым пространством: если внутренних пустых точек несколько, правило самоубийства не даст заполнить ни одну из них.)

**Обёртывание пустого пространства**

Стартовый скрипт использует очень простую логику, оставляя открытые пустые узлы внутри своих сетей (просто исключая точки с `x % 2 === 0 && y % 2 === 0`). Однако намного сильнее — активно искать способы окружить пустое пространство.

Ищите ходы, соединяющие сеть с краем поля и соприкасающиеся с пустым узлом, либо ходы, соединяющие две сети и соприкасающиеся с пустым узлом. Или ищите ход, который соприкасается со своей сетью и разбивает цепь пустых узлов на части.

**Прыжки и «ходы конём»**

Сейчас фракции в большинстве случаев рассматривают только ходы, напрямую связанные со своими или вражескими сетями. Однако, особенно на больших полях, размещение роутера в паре клеток от существующей линии/сети позволяет влиять на бо́льшую территорию по сравнению с более медленными ходами, соединяющими лишь один соседний узел за раз. Попробуйте пропускать один-два узла, ходить по диагонали или комбинировать это в L-образные прыжки (как ход конём в шахматах).

**Сопоставление шаблонов**

В Go есть множество сильных фигур, которые стоит пытаться воспроизводить. Фракции ищут способы проскользнуть по диагонали между сетями игроков и рассечь их. Они также ищут способы обернуться вокруг изолированных вражеских роутеров. Попробуйте собрать небольшую библиотеку сильных фигур, а затем искать их совпадения на поле (или их повороты и отражения). Точные фигуры потребуют некоторого изучения Go, но в интернете об этом много хорошей документации.

**Создание «глаз»**

Если одна сеть полностью окружает две разные несвязанные друг с другом пустые точки, её никогда нельзя захватить. (Если бы внутреннего воздуха было только одно место, противник в итоге мог бы окружить и заполнить его, захватив сеть. Но если их два, правило самоубийства не даст заполнить ни одно из внутренних пустых мест.) Ходы, создающие фигуры в форме восьмёрки или разбивающие окружённую цепь пустых узлов на две меньшие, — очень сильные.

Кроме того, если у противника есть лишь один такой ход, сыграть первым в эту точку, заблокировав его, часто крайне разрушительно и может даже привести к захвату его сети.

&nbsp;

Более глубокое погружение в эту идею потребует написать собственный код для определения цепей фишек (и непрерывных пустых узлов).

- Найдите все ходы, разбивающие пустое пространство и соединяющие две цепи, либо цепь и край поля — как в идее «окружения пустого пространства» выше.
- Применяйте ход на пробной копии поля в памяти, по одному за раз.
- Определите все цепи и непрерывные группы пустых узлов на получившемся поле, а также какого цвета фишки окружают новые группы пустых узлов.
- Отдавайте приоритет ходу, при котором больше всего групп пустых узлов оказываются полностью окружены цветом вашего игрока.
- Либо считайте, со сколькими группами пустых узлов соприкасается каждая своя цепь, и отдавайте приоритет ходам, создающим второй такой «глаз» для своих цепей.
