# Сеть Darkweb

Лёгкие деньги... тайные аугментации... Зов так называемой «тёмной сети» годами звучал в слухах. Погружение в неизведанные и тайные уголки интернета сулит свободу от гнетущей власти и слежки.

Впрочем, оставив привычный интернет позади и обратившись к даркнету, вы идёте на риск... но и получаете потенциальную награду. Человек с нужными знаниями (и достаточным обаянием, чтобы выживать одним только умом) сумеет найти путь на недостаточно защищённые компьютеры этой нерегулируемой сети. Возможно, такой человек, как вы.

Полную документацию NS по этому API см. на [странице документации API](../../../../../markdown/bitburner.darknet.md).

### Структура сети

В отличие от обычной сети BitBurner, darknet постоянно меняется. Серверы иногда перезагружаются, меняют связи с другими серверами или вовсе на неопределённый срок уходят офлайн. Сеть к тому же не является простым деревом: в ней есть петли связей, возвраты и изолированные острова серверов, которые предстоит исследовать.

Из-за нестабильности darknet связь на расстоянии часто затруднена или невозможна. Серверы darknet не доступны свободно откуда угодно. Как правило, взаимодействовать с ними или изменять их можно, только если ваш скрипт работает на напрямую подключённом соседнем сервере. Значит, вам понадобится способ создавать «доставщиков» или «зонды», которые смогут перемещаться по сети и копировать себя дальше.

В некоторых случаях единственный способ добраться до более глубоких частей сети — «прокатиться» на сервере, когда он переезжает в другое место!

**Чтобы получить доступ к darknet, нужно купить `DarkscapeNavigator.exe`**. Сделать это можно командой `buy` в терминале после покупки TOR-роутера. Также есть место в Chongqing, где можно купить доступ.

### Кратко: обзор API darknet

**В конце этого документа есть пример стартового скрипта, показывающий часть этих методов API в деле.**

- `dnet.getServerDetails(hostname)` сообщает подсказку и формат пароля сервера, а также онлайн ли сервер и подключён ли он к текущему.
- `ns.dnet.probe()` позволяет найти серверы darknet, напрямую подключённые к вашему текущему серверу. Используйте это, чтобы находить цели для взлома и переносить на них свой скрипт.
- `await ns.dnet.authenticate(hostname, password)` позволяет подбирать и проверять пароли серверов, напрямую подключённых к серверу, на котором работает ваш скрипт. Угадав верно, вы получаете права администратора и можете использовать `exec` и `scp`, чтобы перенести скрипты на этот сервер.
- На некоторых серверах для подбора пароля нужна интерактивная обратная связь. Используйте `await ns.dnet.heartbleed(hostname)`, чтобы проверить логи этого сервера и получить подсказки после попытки ввода пароля.
- `ns.dnet.connectToSession(hostName, password)` позволяет войти на удалённый сервер darknet по уже известному паролю. Это необходимо для `scp` файлов туда.
- На некоторых серверах часть максимальной RAM заблокирована. Используйте `ns.dnet.memoryReallocation()`, чтобы её освободить.
- На некоторых серверах есть ценные файлы .cache, которые можно открыть функцией `ns.dnet.openCache(fileName)`.
- На серверах darknet можно запускать `ns.dnet.phishingAttack()`, чтобы получить деньги или файлы .cache в зависимости от вашей charisma и характеристики успеха преступлений.
- `ns.dnet.setStasisLink()` фиксирует текущий сервер в состоянии stasis. Это мешает ему перемещаться или уходить в офлайн, а также позволяет получать сессию на этом сервере на расстоянии — как и бэкдор.
- `ns.dnet.induceServerMigration()` можно применять к подключённому серверу, и при достаточном числе применений это заставит его переместиться в новое место в darknet.
- `ns.dnet.promoteStock()` повышает волатильность указанной акции с помощью пропаганды, что может увеличить потенциальную прибыль от торговли ею.

### Глоссарий терминов

**Authenticated (аутентифицирован)** — когда скрипт вызывает dnet.authenticate с верным паролем, происходят две вещи. Во-первых, вы получаете права администратора на сервере (так же, как при NUKE). Во-вторых, скрипт, вызвавший authenticate, получает сессию с целевым сервером. Сессия на целевом сервере нужна для некоторых методов API dnet.

**Session (сессия)** — чтобы делать `scp` или `exec`, нацеленные на сервер darknet, скрипту нужна сессия на нём. Скрипт получает сессию после успешного вызова `dnet.authenticate` с верным паролем. Также сессию можно получить вызовом `dnet.connectToSession` (синхронное API с низким расходом RAM) после того, как хотя бы один скрипт уже успешно прошёл аутентификацию на этом сервере. Учтите, что сессии привязаны к pid (запущенному экземпляру скрипта) — каждому скрипту нужно самостоятельно получить сессию с конкретным сервером darknet, чтобы делать на нём `exec` или `scp`.

**Connected (подключён)** — у каждого сервера сети есть конкретные другие серверы, с которыми он связан. Это те связи, что видны в интерфейсе, серверы, появляющиеся при "scan" в терминале, или те, что видны при вызове dnet.probe. Такое прямое подключение требуется для большинства методов API dnet. Для `ns.exec`, нацеленного на сервер darknet, нужно либо прямое подключение, либо бэкдор, либо stasis-линк (который также ставит бэкдор).

**Offline (офлайн)** — иногда серверы darknet уходят в офлайн. По сути, сервер удаляется, а все работавшие на нём скрипты завершаются. Со временем сервер с тем же именем может снова появиться онлайн, но с другим паролем и полностью очищенным от скриптов. Вызов API, нацеленного на офлайн-сервер, вернёт стандартный/неуспешный ответ, а не исключение, как обычно бывает для несуществующих серверов. Будьте с этим внимательны: список офлайн-серверов очищается при престиже и перезагрузке игры.

### Что учитывать при проектировании скриптов для darknet

Проектируя скрипты для darknet, держите в уме следующие идеи, выбирая свой подход.

#### Darknet нестабилен, и скрипты иногда убиваются, а серверы — исчезают.

- Как сохранить пароли так, чтобы они не терялись, если хранящий их скрипт будет убит?
- Как отслеживать соседние серверы, которые перезагрузились?
- Как восстановиться, если убиты многие или все работающие скрипты?

#### Darknet — запутанная паутина, по которой нельзя легко перемещаться удалённо.

- Как найти путь к серверу, чтобы подключиться к нему через терминал?
- Как обновлять скрипты, когда выходит их новая версия?
- Как доставить скрипты в части сети, не связанные с теми областями, где вы уже находитесь?

#### На darknet много RAM, но получить к ней доступ сложнее, чем в обычной сети.

- Как лучше всего использовать всю эту RAM?
- Как координировать скрипты, использующие эту RAM, когда ситуация меняется?

#### Darknet — настоящая сокровищница данных, если знать, где искать.

- В некоторых файлах данных на серверах darknet есть информация для аутентификации.
- Иногда один сервер аутентифицируется на другом, и эти учётные данные видны в логах сервера или в активных пакетах.
- В некоторых файлах данных можно найти списки часто повторяющихся паролей.

### Навигация по darknet через dnet.probe

Серверы darknet, пытаясь скрыться от официального контроля, не показываются при использовании ns.scan. (Отсюда и название «тёмная сеть»!) Чтобы найти их, сначала нужно купить инструмент `DarkscapeNavigator.exe` командой `buy` в терминале, имея TOR-роутер. Это даёт доступ к API `ns.dnet`. После этого функция `ns.dnet.probe()` покажет список серверов darknet, подключённых к текущему серверу. Учтите, что probe не работает на расстоянии: он не может, в отличие от scan(), нацеливаться на удалённые серверы. Чтобы исследовать тёмную сеть, придётся размещать свои скрипты в ней сервер за сервером.

```js
const nearbyDarknetServers = ns.dnet.probe();
for (const hostname of nearbyDarknetServers) {
  /* do something with each server here */
}
```

### Получение доступа к серверу

Серверы darknet нельзя просто взломать парой готовых открывателей портов, купленных в магазине. Вместо этого нужно найти способ подобрать пароль каждого из них, чтобы запускать на нём скрипты и проходить через него. К счастью, логи каждого сервера дают подсказки и обратную связь по мере попыток угадать пароль, и вы обнаружите, что похожие модели компьютеров имеют похожие уязвимости. Если не понимаете, как подобрать коды аутентификации сервера, поищите заметки на уже разблокированных серверах darknet — там могут быть подсказки для решения некоторых головоломок (а иногда и другие полезные файлы данных).

### Взлом серверов через dnet.authenticate и dnet.heartbleed

Для взаимодействия с серверами darknet нужен пароль. Для начала используйте `dnet.getServerDetails`, чтобы узнать ключевую информацию о сервере. Она даст подсказку по паролю и сообщит, онлайн ли сервер ещё.

Проверить, верен ли предполагаемый пароль, можно функцией `await ns.dnet.authenticate`. (Не забывайте про await — сетевые запросы занимают время!) Чем выше ваша charisma, тем быстрее вы сможете заговорить зубы защите этих уязвимых серверов. Больше потоков тоже ускоряет процесс. Возможно, выгоднее разделить работу между несколькими скриптами, если сумеете их скоординировать. (Учтите: **`dnet.authenticate` может нацеливаться только на близлежащие подключённые серверы**. Проверить, подключён ли сервер к текущему, можно через `dnet.probe` или `dnet.getServerDetails`.)

```js
const details = ns.dnet.getServerDetails(hostname);
if (!details.isConnectedToCurrentServer || !details.isOnline) {
  /* If the server isn't connected or is offline, we can't authenticate */
  return false;
}

if (details.modelId === "ZeroLogon") {
  /* Try to guess the password, based on the model ID and static password hint */
  ns.print(details.passwordHint);
}
```

Пытаясь найти пароль, можно извлекать логи сервера с помощью эксплойта `await ns.dnet.heartbleed`. Это даёт самые свежие логи целевого сервера, где иногда можно найти дополнительные подсказки или намёки на то, почему последняя попытка пароля не сработала. Помимо ваших попыток аутентификации, в логах фиксируется и собственный трафик сервера. Обычно он бесполезен, но иногда содержит интересные подсказки или даже пароли других серверов! (это те же логи, что видны в интерфейсе Darknet при клике на сервер.)

Успешно выполнив `dnet.authenticate` с верным паролем, вы получаете права администратора на сервере (аналогично тому, что делает NUKE.EXE). Это также даёт вашим скриптам сессию с этим сервером, так что можно изменять его `scp` и `exec`.

Найдя верный пароль, вы наверняка захотите сохранить его на будущее (чтобы к серверу могли подключаться другие скрипты, или на случай, если сервер перезагрузится и придётся запускать скрипты заново). Обязательно сохраняйте пароль в надёжном месте, чтобы не потерять его, если ваш скрипт позже остановится.

```js
const result = await ns.dnet.authenticate(hostname, passwordToAttempt);
if (result.success === false) {
  const recentLogResult = await ns.dnet.heartbleed(server, { peek: true });
  ns.print(recentLogResult.logs);
}
```

### Изменение серверов через ns.exec и ns.scp

Серверы darknet защищены паролем. Значит, чтобы получить права администратора, делать `scp` файлов на них или `exec` скриптов на них, нужна сессия. Успешный подбор пароля через `dnet.authenticate` автоматически даёт сессию скрипту, выполнившему команду.

После того как вы аутентифицировались, другие скрипты могут подключиться к тому же серверу через `dnet.connectToSession` с паролем этого сервера. Это синхронная операция, и её можно выполнить на любом расстоянии — то есть не нужно ждать вызова authenticate.

Передача файлов через `scp` возможна на любом расстоянии, как только установлена сессия. А вот для `exec` также требуется, чтобы скрипт запускался с сервера, соседнего и подключённого к целевому, либо чтобы на целевом сервере был бэкдор или stasis-линк. Прямые подключения можно определить через `probe` или `getServerDetails`.

```js
// the darknet server in "hostname" must be either backdoored, stasis linked, or directly connected to the server this script is running on
// to allow exec calls from the current server
if (ns.dnet.getServerDetails(hostname).isConnectedToCurrentServer) {
  ns.dnet.connectToSession(hostname, previouslyDiscoveredPassword);
  ns.scp("my_script.js", hostname);
  ns.exec("my_script.js", hostname, {
    preventDuplicates: true, // This prevents running multiple copies of this script, if there is already one on that server
  });
}
```

### Добыча ресурсов через dnet.openCache и dnet.phishingAttack

Иногда на разблокированных серверах можно найти ценные данные в файлах .cache. В них могут быть деньги, опыт, программы или даже ключи доступа к фондовому рынку. Открыть их можно командой `run` в терминале или функцией `dnet.openCache` из скрипта на этом сервере. Проверить наличие файлов .cache на текущем сервере можно через `ns.ls(ns.getHostname(), '.cache')`.

Получив доступ к серверу darknet, можно начать использовать его в своих целях. Один из вариантов — запустить `dnet.phishingAttack()`, чтобы поднять уровень charisma и попытаться выманить деньги у менее подкованных в технике менеджеров среднего звена. Иногда такая попытка вдобавок приносит файлы .cache!

### Освобождение дополнительной RAM через dnet.memoryReallocation

Серверы darknet уже кому-то принадлежат, и на них часто уже что-то делают. При первой аутентификации на некоторых из них часть RAM будет «занята» (явно бестолковыми) нуждами владельца, и её нужно... освободить. Полностью освободить эту RAM для себя можно повторными вызовами `dnet.memoryReallocation`. Обычно после полной очистки RAM обнаруживаются оставленные ценные файлы .cache.

### Стабилизация сервера через dnet.setStasisLink

Серверы darknet печально известны своей ненадёжностью. Они могут перезагружаться или уходить в офлайн, убивая все работающие на них скрипты. Также они могут уходить из зоны, где вы работаете. Чтобы бороться с этим, у вас есть ограниченное количество доступных «stasis-линков», которые можно наложить на текущий сервер (или снять с него) функцией `dnet.setStasisLink`. Наложение stasis-линка на сервер позволяет делать `dnet.connectToSession`, `exec` и `connect` из терминала на любом расстоянии.

Список серверов с наложенным stasis-линком можно посмотреть через `dnet.getStasisLinkedServers`, а текущий лимит — через `dnet.getStasisLinkLimit`.

### Перемещение серверов через dnet.induceServerMigration

Некоторые части darknet изолированы друг от друга — образуют «разрывы». Пересечь их можно только «прокатившись» на сервере во время его перемещения. Ждать удобного момента перемещения ненадёжно, но этот процесс можно ускорить.

Повторные вызовы `dnet.induceServerMigration` накапливают заряд на целевом сервере, в итоге вынуждая его переместиться. (Часто он перемещается глубже в сеть, но направление перемещения не гарантировано.) `dnet.induceServerMigration` может нацеливаться только на серверы, напрямую подключённые к текущему серверу скрипта, но эффект накапливается, если несколько серверов воздействуют на один и тот же.

### Повышение волатильности акции через dnet.promoteStock

Волатильность акции определяет, насколько сильно может измениться её цена при каждом обновлении фондового рынка. Повторные вызовы `dnet.promoteStock` позволяют нацелиться на акцию и значительно поднять эту волатильность. Это не меняет её прогноз так, как это делают опции stock у hack() или grow(), — акция по-прежнему будет двигаться в том же общем направлении, вверх или вниз. Но аккуратное применение `dnet.promoteStock` к ключевым акциям, которыми вы владеете (или хотите купить, или на которые у вас есть опционы), может увеличить вашу прибыль от фондового рынка.

/** @param {NS} ns */
export async function main(ns) {
  while (true) {
    // Get a list of all darknet hostnames directly connected to the current server
    const nearbyServers = ns.dnet.probe();

    // Attempt to authenticate with each of the nearby servers, and spread this script to them
    for (const hostname of nearbyServers) {
      const authenticationSuccessful = await serverSolver(ns, hostname);
      if (!authenticationSuccessful) {
        continue; // If we failed to auth, just move on to the next server
      }

      // If we have successfully authenticated, we can now copy and run this script on the target server
      ns.scp(ns.getScriptName(), hostname);
      ns.exec(ns.getScriptName(), hostname, {
        preventDuplicates: true, // This prevents running multiple copies of this script
      });
    }

/** Attempts to authenticate with the specified server using the Darknet API.
 * @param {NS} ns
 * @param {string} hostname - the name of the server to attempt to authorize on
 */
export const serverSolver = async (ns, hostname) => {
  // Get key info about the server, so we know what kind it is and how to authenticate with it
  const details = ns.dnet.getServerDetails(hostname);
  if (!details.isConnectedToCurrentServer || !details.isOnline) {
    // If the server isn't connected or is offline, we can't authenticate
    return false;
  }
  // If you are already authenticated to that server with this script, you don't need to do it again
  if (details.hasSession) {
    return true;
  }

  switch (details.modelId) {
    case "ZeroLogon":
      return authenticateWithNoPassword(ns, hostname);

    // TODO: handle other models of darknet servers here

    // TODO: get recent server logs with `await ns.dnet.heartbleed(hostname)` for more detailed logging on failed auth attempts

    default:
      ns.tprint(`Unrecognized modelId: ${details.modelId}`);
      return false;
  }
};

/** Authenticates on 'ZeroLogon' type servers, which always have an empty password.
 *  @param {NS} ns
 *  @param {string} hostname - the name of the server to attempt to authorize on
 */
const authenticateWithNoPassword = async (ns, hostname) => {
  const result = await ns.dnet.authenticate(hostname, "");
  // TODO: store discovered passwords somewhere safe, in case we need them later
  return result.success;
};
