# Smart Supply

## Логика работы

Создайте функцию `getLimitedRawProduction`:

- Вычислите `RawProduction`.
- Умножьте `RawProduction` на 10.
- Вычислите `RequiredStorageSpaceOfEachOutputUnit` — чистое изменение занятого места на складе при производстве одной единицы продукции.
- Если `RequiredStorageSpaceOfEachOutputUnit` больше 0:
  - Вычислите `MaxNumberOfOutputUnits` — максимальное количество единиц, которое можно произвести и разместить в свободном месте на складе.
  - При необходимости ограничьте `RawProduction` значением `MaxNumberOfOutputUnits`.

Создайте словарь `SmartSupplyData`. Ключ — `${divisionName}|${city}`. Значение — `TotalRawProduction`, которое будет вычислено ниже.

После состояния PURCHASE:

- Инициализируйте `TotalRawProduction` нулём.
- Если подразделение производит материалы: вызовите `getLimitedRawProduction` и прибавьте возвращённое значение к `TotalRawProduction`.
- Если подразделение производит продукты:
  - Пройдитесь по всем продуктам подразделения.
  - Если продукт готов, вызовите `getLimitedRawProduction` и прибавьте возвращённое значение к `TotalRawProduction`.
- Запишите `TotalRawProduction` в `SmartSupplyData`.

Перед состоянием PURCHASE:

- Проверьте, не переполнен ли склад. Если переполнен — предупредите игрока и попробуйте исправить ситуацию.
- Найдите требуемое количество каждого входного материала для производства материала/продукта:
  - Возьмите `TotalRawProduction` из `SmartSupplyData`.
  - Умножьте `TotalRawProduction` на коэффициент входного материала.
- Определите, какой входной материал даёт наименьшее количество выходных единиц.
- Приведите все входные материалы к этому наименьшему количеству.
- Вычислите суммарный объём всех входных материалов, которые вы собираетесь купить.
- Если свободного места не хватает, примените к требуемому количеству понижающий множитель, чтобы не переполнить склад.
- Вычтите из требуемого количества число уже хранящихся единиц входного материала.
- Купите входные материалы.

## Определение переполнения склада

Склад может переполниться по разным причинам. Частый случай — когда логика расчёта требуемого количества входных материалов не учитывает свободное место и уже хранящиеся на складе единицы входных материалов. Тогда склад забивается избыточными входными материалами, и производство полностью останавливается, потому что произведённые единицы негде разместить.

Для каждого случая нужно найти способ обнаружить переполнение и устранить его. В описанном выше случае подойдёт простая эвристика:

- Создайте словарь `WarehouseCongestionData`. Ключ — `${divisionName}|${city}`. Значение — количество раз, когда вы заподозрили переполнение склада.
- В каждом цикле проверяйте `material.productionAmount` и `product.productionAmount` выходного материала/продукта.
  - Если `productionAmount` равно 0, увеличьте значение для этого склада в словаре на 1. Если нет — обнулите значение.
  - Если значение больше 5, склад с высокой вероятностью переполнен.
- Эвристика основана на наблюдении: когда склад забит избыточными входными материалами, производство полностью останавливается, то есть `productionAmount` равно 0. Мы ждём 5 раз, чтобы снизить количество ложных срабатываний.
- В момент запуска вашего скрипта Smart Supply `productionAmount` выходного материала/продукта может быть равно 0, потому что в предыдущих циклах производством никто не управлял.

Если избыточные входные материалы всё же накопились, самая простая мера — выбросить их все. Это неэффективно, но это самый быстрый способ перезапустить производственную линию.
