# Coding Contracts

Coding Contracts — механика, позволяющая получать награды за решение задач по программированию.

Coding Contracts — это файлы с расширением `.cct`.
Обращаться к ним можно через [Терминал](terminal.md) или из [скриптов](scripts.md) через [Coding Contract API](../../../../../markdown/bitburner.codingcontract.md).

У каждого контракта ограниченное число попыток.
Если слишком много раз дать неверный ответ и исчерпать попытки, контракт самоуничтожится (удалит себя).

Coding Contracts генерируются случайно и появляются со временем. Сначала вам будет попадаться лишь небольшой набор контрактов попроще, но по мере продвижения по игре откроются и более сложные.

Они могут появляться на [серверах](servers.md) вне darknet, не принадлежащих игроку (`Server.purchasedByPlayer` равно false).

## Генерация контрактов

### Онлайн

Каждые 10 минут игра делает три независимые попытки сгенерировать контракт на обычных серверах, каждая с базовой
вероятностью 25%. Эта вероятность снижается в зависимости от общего числа контрактов на всех серверах. В большинстве случаев можно
считать, что вероятность успеха каждой попытки — около 25%.

### Офлайн

Когда игра запускается после офлайна, время офлайна используется для расчёта количества попыток генерации.
Правила и вероятности те же, что и при онлайн-генерации.

### Dark Net

Открытие файлов-кешей на серверах [darknet](../programming/darknet.md) тоже может породить контракт, но с
меньшими наградами. Награды у таких контрактов на 50% ниже, чем у случайно сгенерированных на обычных серверах.

## Запуск в Терминале

Чтобы запустить Coding Contract в [Терминале](terminal.md), используйте команду `run`:

    $ run some-contract.cct

Откроется всплывающее окно.
В нём будет условие задачи, количество оставшихся попыток и поле для ответа.

## Работа через скрипты

См. [Coding Contract API](../../../../../markdown/bitburner.codingcontract.md).
Чем больше контрактов вы решаете, тем утомительнее работать с ними через [Терминал](terminal.md).
Стоит использовать API, чтобы автоматизировать разные части решения.
Например, у некоторых контрактов длинные решения, а у некоторых — ещё длиннее.
Возможно, вам захочется автоматизировать отправку решения через API, а не копировать длинный ответ в поле ввода.
Через API также можно узнать полезную информацию о контракте: сколько осталось попыток, какого он типа и какова его сложность.
А ещё им можно тестировать свой алгоритм для конкретного типа контрактов, [создавая пробные контракты](../../../../../markdown/bitburner.codingcontract.createdummycontract.md).

Но использование API не бесплатно.
Как и у большинства функций в других API, почти у всех функций здесь есть расход RAM.

В зависимости от того, какие функции вы используете, изначальной [RAM](ram.md) на домашнем сервере может не хватить для работы с разными функциями API.
Если вы собираетесь пользоваться этими API, рассчитывайте на улучшение [RAM](ram.md) домашнего сервера.

Функция [`getContractTypes`](../../../../../markdown/bitburner.codingcontract.getcontracttypes.md) бесплатна и возвращает список всех типов контрактов, имеющихся сейчас в игре.

## Отправка решений

### Общие правила

Разные типы задач требуют разных типов решений.
Где-то это числа, где-то строки или массивы.

Если контракт требует конкретный формат решения — используйте его.
В остальных случаях при отправке решений следуйте этим правилам:

- Строковые решения (например, Shortest Path in a Grid) **не** должны быть окружены кавычками (если это специально не требуется). Например, если ваш ответ — `foo` (3 символа: f, o, o), отправляйте именно эти 3 символа. Не отправляйте `"foo"` (5 символов).
  Включать нужно только те кавычки, которые действительно являются частью строки-решения.
- Для решений в виде массива строк (например, Generate IP Addresses) строковые значения нужно заключать в двойные кавычки. Не используйте одинарные кавычки (`''`) или обратные (\`\`). Например, если ваш ответ — массив из `foo` (3 символа: f, o, o) и `bar` (3 символа: b, a, r), отправляйте `["foo", "bar"]`. Не отправляйте `['foo', 'bar']`.
- Решения-массивы отправляются с элементами через запятую.
- Числовые решения отправляются обычным образом, как и ожидается.
- Внимательно читайте условие. Некоторые контракты (например, «Square Root») прямо указывают ожидаемый формат решения.
- Если формат решения не строковый, преобразовывать ответ в строку не нужно. Если всё же преобразуете — внимательно прочитайте следующие разделы.

### Преобразование в строку

Ради удобства (например, отправки ответа через интерфейс) и обратной совместимости игра принимает строковый ответ даже тогда,
когда формат решения не строковый. В таких случаях игра сама приводит вашу строку к нужному формату. Но
у такого преобразования множество подводных камней.

Преобразование в строку имеет значение только при отправке ответа через интерфейс (ответ, набранный в текстовом поле, всегда строка). При вызове API `ns.codingcontract.attempt` никогда не преобразуйте нестроковый ответ в строку, если это специально не требуется.

Во-первых, для массивов внешняя пара скобок необязательна. Например, оба следующих формата корректны:

- `1,2,3`
- `[1,2,3]`

Примечание:

- Если решение — многомерный массив, то всем массивам, кроме внешнего, скобки НУЖНЫ. Например, массив массивов можно отправить в одном из видов:
  - `[1,2],[3,4]`
  - `[[1,2],[3,4]]`
- Пустая строка преобразуется в пустой массив.
- `"[]"` (строка, состоящая только из 2 скобок; двойные кавычки в эту строку не входят) преобразуется в пустой массив.

Во-вторых, в интерфейсе:

- Если ваш ответ — пустая строка, оставьте текстовое поле пустым. НЕ используйте `""`, `''` или \`\`.
- Если ответ — непустая строка, наберите её как есть. Например, если ответ — слово `foo`, наберите `foo` (3 символа: f, o, o). НЕ добавляйте никаких кавычек.
- Если ответ — массив, содержащий строки, используйте для строк двойные кавычки. НЕ используйте одинарные или обратные. Например, если ваш ответ — массив со словом `foo`, наберите `["foo"]` (7 символов: квадратная скобка, двойная кавычка, f, o, o, двойная кавычка, квадратная скобка). Скобки, как сказано выше, необязательны, но мы рекомендуем их ставить.

### Советы

Если контракт не ожидает строку, не отправляйте строку. Для контрактов, где решение не строковое,
ваш ответ никогда не должен быть строкой, поэтому отправка строки означает, что вы преобразовали нестроковый ответ
в строку. Как правило, это ошибка.

Помните, что преобразование в строку существует ради удобства интерфейса и обратной совместимости. Если вы используете NS API, никаких
преобразований в строку делать не нужно, если это специально не требуется.

Например, пусть контракт требует ответ в виде массива строк, и вы выяснили, что это
строки `foo` и `bar`. Ваш код должен выглядеть так:

```js
const firstString = "foo";
const secondString = "bar";
const answer = [firstString, secondString];
ns.codingcontract.attempt(answer, "filename.cct");
```

Никакого преобразования!

В разделе «Общие правила» выше про решения-массивы строк сказано: `Не используйте одинарные или обратные кавычки`.
Однако этот код работает:

<!-- prettier-ignore -->
```js
const firstString = 'foo'; // Single quotes
const secondString = 'bar'; // Single quotes
const answer = [firstString, secondString];
ns.codingcontract.attempt(answer, "filename.cct");
```

Почему так?

В этом коде вы отправляете массив из 2 строк. В JS `"foo"` и `'foo'` — одна и та же строка. Но если вы
отправляете ответ строкой, вам приходится преобразовывать массив в строку, а строка `["foo", "bar"]` — не то же самое,
что строка `['foo', 'bar']`.

Внутри мы используем `JSON.parse` для преобразования строкового ответа, а `['foo', 'bar']` не является корректным строковым представлением
массива. В JSON строка должна быть заключена в двойные кавычки. Одинарные или обратные кавычки не допускаются.

Это ещё одна причина не преобразовывать ответ в строку без необходимости. Если отправлять массив как есть,
о типах кавычек можно не думать вовсе.

Разберём ещё один пример:

```js
const firstString = "foo";
const secondString = "bar";
const answer = [firstString, secondString];
ns.codingcontract.attempt(answer.toString(), "filename.cct");
ns.codingcontract.attempt(String(answer), "filename.cct");
```

НЕ вызывайте toString() и подобные методы для преобразования массива строк в строку. `["foo", "bar"]` превратится
в `foo,bar`. Для контрактов, ожидающих массив строк, отправка такой строки приведёт к тому, что она будет прочитана как
`[foo,bar]` и передана в `JSON.parse`. Но `[foo,bar]` — некорректный JSON (нет двойных кавычек), так что
ваш ответ окажется неверным.

## Награды

Сейчас за решение Coding Contract возможны четыре вида награды:

- [Репутация](reputation.md) в конкретной [фракции](factions.md)
- [Репутация](reputation.md) во всех [фракциях](factions.md), в которых вы состоите
- [Репутация](reputation.md) в конкретной [компании](companies.md)
- Деньги

Тип награды выбирается случайно в момент появления контракта. Если на момент решения выбранная награда неприменима (например, не выполнены
требования), происходит откат к альтернативному типу:

- Репутация в конкретной фракции ⇒ деньги
- Репутация во всех фракциях ⇒ деньги
- Репутация в компании ⇒ репутация в конкретной фракции или во всех фракциях (по 50% на каждый вариант).
  Если запасная награда тоже неприменима, наградой по умолчанию становятся деньги.

Например, если контракт настроен на награду «репутация во всех фракциях», а вы на момент отправки решения не вступили ни в одну фракцию,
вы получите деньги.

Размер награды зависит от сложности задачи в Coding Contract.

## Примечания

- Команда `scp` и API `ns.scp` с Coding Contracts не работают.
