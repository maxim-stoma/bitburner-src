# Руководство по миграции на «Netscript 2»

В прежних версиях игра поддерживала два формата скриптов:

- Файлы `.script` (их также называют «Netscript 1» или «NS1») выполняются интерпретатором, основанным на версии JavaScript от 2009 года (ES5).

- Файлы `.js` (их также называют «Netscript 2» или «NS2») — это нативный JavaScript, который выполняется непосредственно браузером. Все современные возможности JavaScript, которые поддерживает ваш браузер, доступны и в файлах `.js`, потому что они исполняются как нативный js.

Поддержка запуска файлов `.script` была убрана в версии 3.0.

## Зачем вообще что-то менять?

Поскольку любой ES5-код по-прежнему является корректным JavaScript, может показаться странным, что старый код не работает просто после переименования в `.js`. В этом разделе разобраны ключевые различия.

- **Способ доступа к API**: в файлах `.script` игровое API доступно на верхнем уровне файла, как если бы находилось в глобальной области видимости. В файлах `.js` игровое API передаётся аргументом в функцию `main` скрипта и на верхнем уровне недоступно.
- **Различия в выполнении**: запуск файла `.script` начинает выполнение кода с начала файла. Запуск файла `.js` вызывает функцию `main` (передавая игровое API первым аргументом, обычно называемым `ns`).
- **Различия в таймингах**: в файлах `.script` между каждой инструкцией автоматически вставляется задержка. В файлах `.js` код выполняется нативно, поэтому встроенных задержек нет, и все нужные задержки приходится добавлять вручную.

## Базовые шаги миграции скрипта

1. Оберните весь скрипт в экспортируемую функцию main:

```js
/** @param {NS} ns */
export async function main(ns) {
  // your code here
}
```

2. Добавьте префикс `ns.` ко всем игровым функциям и объектам (например, `ns.hack()` или `ns.args`).
3. Если функция возвращает `Promise`, перед ней нужно поставить ключевое слово `await` (с JSDoc-комментарием можно навести курсор на функцию и увидеть тип возвращаемого значения). Учтите, что `await` разрешён только внутри функций, объявленных как `async`, и что вызовы ваших собственных `async`-функций тоже обычно следует await-ить.
4. Поскольку принудительных задержек больше нет, бесконечный цикл без ручной задержки подвесит игру. В таких циклах нужно хотя бы раз делать `await` какой-нибудь функции (обычно `ns.sleep()`).
5. Ключевое слово `var` в современном js для объявления переменных используется редко. Предпочтительны `let` или `const` (если переменная больше не переприсваивается). Эта правка необязательна.

## Пример миграции

Оригинал (`early-hacking-template.script`):

```js
var target = "n00dles";
var moneyThresh = getServerMaxMoney(target) * 0.9;
var securityThresh = getServerMinSecurityLevel(target) + 5;

while (true) {
  if (getServerSecurityLevel(target) > securityThresh) {
    weaken(target);
  } else if (getServerMoneyAvailable(target) < moneyThresh) {
    grow(target);
  } else {
    hack(target);
  }
}
```

После миграции (`early-hacking-template.js`):

```js
/** @param {NS} ns */
export async function main(ns) {
  const target = "n00dles";
  const moneyThresh = ns.getServerMaxMoney(target) * 0.9;
  const securityThresh = ns.getServerMinSecurityLevel(target) + 5;

  while (true) {
    if (ns.getServerSecurityLevel(target) > securityThresh) {
      await ns.weaken(target);
    } else if (ns.getServerMoneyAvailable(target) < moneyThresh) {
      await ns.grow(target);
    } else {
      await ns.hack(target);
    }
  }
}
```
