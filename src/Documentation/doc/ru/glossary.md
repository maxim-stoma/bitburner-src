# Глоссарий терминов

Этот файл — справочник по терминологии русского перевода документации. Он нужен, чтобы одни и те же
игровые понятия назывались одинаково во всех файлах.

## Общие принципы

1. **Названия игровых сущностей не переводятся.** Всё, что игрок видит в интерфейсе игры на английском
   и не может найти по русскому названию (BitNode, Source-File, Bladeburner, Hacknet, названия фракций,
   серверов, программ, аугментаций, материалов корпорации), остаётся латиницей.
2. **Общие понятия переводятся.** Слова, которые в русском IT-контексте имеют устоявшийся перевод
   (сервер, скрипт, память, репутация, деньги, опыт), переводятся.
3. **Код не трогается.** Имена функций Netscript API, пути к файлам, команды терминала, содержимое
   блоков кода и инлайн-кода остаются без изменений — даже если рядом в тексте используется русский
   термин.
4. **При первом появлении** непереводимого термина в файле уместно дать пояснение в скобках, дальше
   использовать сам термин.
5. **Склонение.** Латинские термины склоняются по смыслу без дефисов и окончаний: «в BitNode 4»,
   «получить Source-File», «у Bladeburner». Прижившиеся заимствования склоняются как русские слова:
   «аугментации», «скриптом», «нодами».

## Стиль

- Обращение к игроку — на «вы» без заглавной буквы.
- Заголовки — по правилам русского языка: с заглавной только первое слово и имена собственные.
- «Вы можете сделать X» лучше заменять на «Сделайте X» / «X делается так», где это не искажает смысл.
- Единицы: `$` перед суммой сохраняем как в оригинале; `GB`, `TB` — как есть.

## Справочник NS API (markdown/ru/)

Дополнительные правила специально для перевода `markdown/` (автосгенерированный справочник API из
`NetscriptDefinitions.d.ts`). Используются вместе с общими принципами выше.

### Что переводим

- Слово `Home` в хлебных крошках → `Главная`. Остальные сегменты крошек (`bitburner`, `NS`, конкретные
  имена методов/классов) — не трогаем, это идентификаторы кода.
- Человекочитаемое summary-предложение сразу под заголовком (например, «Steal a server's money.») —
  переводим. Сам заголовок вида `## NS.hack() method` / `## NS.args property` — не переводим
  (это идентификатор + служебное слово method/property/interface/class, которое тоже часть шаблона
  генератора и не трогается).
- Текст описания в блоках `Remarks` (часто это и есть основной, самый содержательный текст страницы,
  а не короткая сводка под заголовком) — переводим полностью, включая фразу `RAM cost: X GB` →
  `Расход RAM: X ГБ`.
- Текст в столбце `Description` таблиц параметров/свойств/методов — переводим. Значения в столбцах
  `Parameter`, `Type`, `Modifiers` — не переводим (это идентификаторы/типы TypeScript).
- Текст описания под `**Returns:**` (что означает возвращаемое значение) — переводим; сам тип
  (`Promise&lt;number&gt;` и т.п.) — не переводим.

### Не трогаем никогда

- Блок `**Signature:**` целиком (код TypeScript).
- Блок `## Example` / `## Пример` целиком (код JS/TS внутри — не текст-пояснение перед ним, если он есть).
- Инлайн-код `` `...` ``.
- Ссылки `[текст](./bitburner.xxx.md)` — сам путь не трогаем; текст ссылки не трогаем, если это
  идентификатор (имя метода/класса); если это человекочитаемая фраза-ссылка (редко) — можно перевести.
- Комментарий `<!-- Do not edit this file... -->` в начале каждого файла — не трогаем.
- HTML-заглушки вида `<!-- -->` внутри текста (используются генератором для разделения инлайн-кода) —
  не трогаем, просто сохраняем на тех же местах.
